# Docker guide

## Compose files

| File | Application images | Published host ports |
|------|--------------------|----------------------|
| `docker-compose.yml` | Pulls images from GHCR | Web and backend only |
| `docker-compose.dev.yml` | Builds from the current checkout | All services needed for local and hybrid development |

Both files start the complete stack: two PostgreSQL databases, Redis, ClickHouse,
MinIO, object-storage, scalars, backend, and web. Persistent data is stored under
`./storage/`.

## Deployment stack

The default Compose file uses these images:

```text
ghcr.io/${GHCR_NAMESPACE:-malchul}/experiment-tracker-backend:${IMAGE_TAG:-latest}
ghcr.io/${GHCR_NAMESPACE:-malchul}/experiment-tracker-scalars:${IMAGE_TAG:-latest}
ghcr.io/${GHCR_NAMESPACE:-malchul}/experiment-tracker-object-storage:${IMAGE_TAG:-latest}
ghcr.io/${GHCR_NAMESPACE:-malchul}/experiment-tracker-web:${IMAGE_TAG:-latest}
```

`GHCR_NAMESPACE` is the GitHub user or organization that owns the packages.
`IMAGE_TAG` is the manually selected workflow tag or a full commit SHA.

Start it from the repository root:

```bash
docker compose pull
docker compose up -d
docker compose ps
```

Only `web` and `backend` are reachable from the host by default:

| Host port | Service |
|-----------|---------|
| `${WEB_PORT:-3000}` | web |
| `${BACKEND_PORT:-8000}` | backend |

PostgreSQL, Redis, ClickHouse, MinIO, scalars, and object-storage communicate only
over the Compose network. If GHCR packages are private, authenticate first with
`docker login ghcr.io`.

Set `IMAGE_TAG` to the full commit SHA generated by the image workflow to deploy
an immutable version:

```bash
IMAGE_TAG=<full-commit-sha> docker compose pull
IMAGE_TAG=<full-commit-sha> docker compose up -d
```

Put `IMAGE_TAG` in root `.env` to avoid repeating it.

## Build and publish images

The GitHub Actions workflow at `.github/workflows/build-images.yml` is
`workflow_dispatch` only. It never runs because of a push, merge, or pull request.

Run it from GitHub:

1. Open **Actions** → **Build and publish Docker images**.
2. Select **Run workflow** and the branch to build.
3. Enter an additional image tag, normally `latest` or a release such as `v1.2.0`.
4. Start the workflow.

The workflow builds all four application Dockerfiles with the repository root as
the build context and pushes the selected tag plus the full commit-SHA tag to
GHCR. It uses the repository `GITHUB_TOKEN`; the workflow grants
`packages: write`. Images are published under the repository owner's lowercase
GHCR namespace.

`PUBLIC_API_BASE_URL` is read when the web container serves requests and injected
into the frontend. Changing the browser-facing backend URL requires recreating
the web container, not rebuilding its image.

## Development stack

Use `docker-compose.dev.yml` when changing code, building locally, or connecting
host-run services to containerized dependencies:

```bash
docker compose -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.dev.yml logs -f backend
```

The development file publishes these default ports:

| Host port | Service |
|-----------|---------|
| 3000 | web |
| 8000 | backend |
| 8001 | scalars |
| 8002 | object-storage |
| 5435 | backend PostgreSQL |
| 5434 | object-storage PostgreSQL |
| 6380 | Redis |
| 8123 | ClickHouse HTTP |
| 9000 / 9001 | MinIO API / console |

Override host ports and credentials in root `.env`; see `.env.example`.

Build one application image:

```bash
docker compose -f docker-compose.dev.yml build backend
docker compose -f docker-compose.dev.yml build scalars
docker compose -f docker-compose.dev.yml build object-storage
docker compose -f docker-compose.dev.yml build web
```

Force a clean rebuild:

```bash
docker compose -f docker-compose.dev.yml build --no-cache object-storage scalars backend web
docker compose -f docker-compose.dev.yml up -d --force-recreate
```

The `scripts/docker-up-public.sh` helper uses the development Compose file and
sets the requested browser API URL as runtime configuration.

## Configuration

Important root `.env` values:

| Variable | Purpose |
|----------|---------|
| `GHCR_NAMESPACE` | GHCR owner/organization used by deployment Compose |
| `IMAGE_TAG` | Selected workflow tag or full commit SHA used by deployment Compose |
| `WEB_PORT`, `BACKEND_PORT` | Host ports published by deployment Compose |
| `JWT_SECRET`, `ADMIN_PANEL_KEY` | Backend secrets |
| `ALLOWED_ORIGINS` | Browser origins accepted by backend |
| `OBJECT_STORAGE_ALLOWED_ORIGINS` | Browser origins accepted by object-storage |
| `PUBLIC_API_BASE_URL` | Browser-reachable backend URL injected by the web container |
| `SERVER_API_BASE_URL` | Internal URL used by Next.js route handlers |

`PUBLIC_API_BASE_URL` and `SERVER_API_BASE_URL` may be identical outside Docker.
In Compose, browsers use the published backend URL while Next.js artifact proxy
routes use the private `http://backend:8000` address.

For a public hostname, set `PUBLIC_API_BASE_URL` to the public backend URL, set
both CORS variables to the UI origin, then recreate the stack.

## Stop, update, and reset

Deployment stack:

```bash
docker compose down
docker compose pull
docker compose up -d
```

Development stack:

```bash
docker compose -f docker-compose.dev.yml down
docker compose -f docker-compose.dev.yml up -d --build
```

`docker compose down` does not remove data under `./storage/`. Removing that
directory resets databases and blobs and is destructive.

## Dockerfiles

All application Dockerfiles require the repository root as build context:

```bash
docker build -f python/backend/Dockerfile -t experiment-tracker-backend .
docker build -f python/scalars_service/Dockerfile -t experiment-tracker-scalars .
docker build -f python/object_storage/Dockerfile -t experiment-tracker-object-storage .
docker build -f apps/web/Dockerfile -t experiment-tracker-web .
```
