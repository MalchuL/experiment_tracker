# 0.12.9

## SDK (`experiment-tracker-sdk` 0.12.9)

- **Init progress starts at 0.** `RunSample.init()` (CLI `experiment-tracker run`) now calls `progress(0)` instead of `progress(1)` when marking an experiment as running, so new runs begin at 0% rather than 1%.
- **Float progress rounding.** `ExpTracker.progress()` continues to treat floats as 0–1 fractions, clamp to `[0, 1]`, and round to an integer percent (`0.255` → `26`). Added unit tests in `python/sdk/tests/test_exp_tracker_progress.py`.

## Backend

- **`started_at` on running status.** When an experiment is created or updated with `status=running`, the API sets `started_at` to the current UTC timestamp. A repeated update with `status=running` resets `started_at` to now.

## Scalars service

- **Longer read cache TTL.** Default `SCALARS_CACHE_TTL_SECONDS` increased from 60 seconds to **15 minutes** (900). The in-memory cache factory reads this setting instead of a hardcoded value; override via env if needed. Writes still invalidate affected experiment cache entries immediately.

## Web UI

- **Compare tab persistence.** The compare view (Files / Metrics / HParams) remembers the selected tab per project in `localStorage`, using the same controlled-tabs pattern as the experiment sidebar. Key: `experiment-tracker:experiment-data-compare:compare:<projectId>:active-tab`.
- **Final artifact markdown preview.** `.md` files on the experiment details Artifacts tab render as formatted GFM markdown instead of raw text.
- **Artifact step slider ticks.** Logged-object step sliders (global card slider and per-experiment override slider) show tick marks at every logged step; the thumb stays on top.
- **Docs topic groups without index pages.** Sidebar and header doc nav groups with no landing page (e.g. Reference, Contributing) highlight when a child page is active and expand/collapse when the group label is clicked.
- **Scalars compare hover with duplicate experiment names.** Metric chart compare/in-view hover keys rows by experiment id, dedupes one row per experiment per step, and still shows the plain experiment name (color distinguishes runs with the same name).
- **Scalars “in view” hover mode.** Metric charts add a third hover mode cycled via the single Plotly mode-bar control: **all** → **in view** → **nearest**. In-view shows every experiment at the hovered step whose plotted y value falls inside the current y-axis range, hiding runs above or below a zoomed viewport.
