# 0.12.9

## SDK (`experiment-tracker-sdk` 0.12.9)

- **Init progress starts at 0.** `RunSample.init()` (CLI `experiment-tracker run`) now calls `progress(0)` instead of `progress(1)` when marking an experiment as running, so new runs begin at 0% rather than 1%.
- **Float progress rounding.** `ExpTracker.progress()` continues to treat floats as 0–1 fractions, clamp to `[0, 1]`, and round to an integer percent (`0.255` → `26`). Added unit tests in `python/sdk/tests/test_exp_tracker_progress.py`.

## Backend

- **`started_at` on running status.** When an experiment is created or updated with `status=running`, the API sets `started_at` to the current UTC timestamp. A repeated update with `status=running` resets `started_at` to now.

## Scalars service

- **Longer read cache TTL.** Default `SCALARS_CACHE_TTL_SECONDS` increased from 60 seconds to **15 minutes** (900). The in-memory cache factory reads this setting instead of a hardcoded value; override via env if needed. Writes still invalidate affected experiment cache entries immediately.
- **Filtered scalar reads.** Scalar read APIs accept repeated `scalar_name` filters and `store_cache=false`; `scalar_name` omitted still loads every scalar. A lightweight scalar-name endpoint reads names from the existing mapping table without loading point values.

## Web UI

- **Compare tab persistence.** The compare view (Files / Metrics / HParams / Scalars) remembers the selected tab per project in `localStorage`, using the same controlled-tabs pattern as the experiment sidebar. Key: `experiment-tracker:experiment-data-compare:compare:<projectId>:active-tab`.
- **Compare Scalars tab.** The compare view adds a **Scalars** tab for detailed scalar comparison across the currently selected experiments. Users can add independent scalar plots, choose a scalar with a searchable picker, set smoothing, optional step min/max bounds, manually refetch, resize plot height, and use the same Plotly hover-mode toolbar control as the Scalars page. Points and step bounds are applied on Enter or blur, so typing alone does not refetch. Compare plot data fetches only the selected scalar and disables scalar-service cache storage for those detailed requests.
- **Compare plot config persistence.** Compare Metrics and Scalars plot configurations are saved per project in `localStorage`; fetched metric/scalar values are not serialized. Scalar point-count values are capped only when saved to localStorage, while the live input and fetch can use the full entered value.
- **Compare Metrics plot polish.** Metrics compare plots support persisted plot config and height resizing, and vertical experiment separator lines are kept for every valid experiment slot without emitting Recharts `NaN` SVG coordinate warnings.
- **Final artifact markdown preview.** `.md` files on the experiment details Artifacts tab render as formatted GFM markdown instead of raw text.
- **Artifact step slider ticks.** Logged-object step sliders (global card slider and per-experiment override slider) show tick marks at every logged step; the thumb stays on top.
- **Docs topic groups without index pages.** Sidebar and header doc nav groups with no landing page (e.g. Reference, Contributing) highlight when a child page is active and expand/collapse when the group label is clicked.
- **Scalars compare hover with duplicate experiment names.** Metric chart compare/in-view hover keys rows by experiment id, dedupes one row per experiment per step, and still shows the plain experiment name (color distinguishes runs with the same name).
- **Scalars “in view” hover mode.** Metric charts add a third hover mode cycled via the single Plotly mode-bar control: **all** → **in view** → **nearest**. In-view shows every experiment at the hovered step whose plotted y value falls inside the current y-axis range, hiding runs above or below a zoomed viewport.
- **Metrics controls toggle.** The project Metrics page left rail (label, filters, layout, metric order) can be hidden to give the table more space. Use the **Controls** outline button in the metrics grid toolbar (left of **Download**); the panel collapses with a width transition and can be shown again from the same button.
- **Paginated list completion.** Full-list Web UI calls now drain paginated responses instead of showing only the first page for API tokens, project hypotheses, teams, reports, scalar `last_logged` polling, and incremental scalar/artifact refresh fetches.
